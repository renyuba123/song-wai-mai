# 展览行为采集函数

游戏页把关键事件和两秒一次的位置采样批量 POST 到这个 HTTP 云函数，
函数清洗后写入 CloudBase PostgreSQL 的 `behavior_events` 表。
客户端只带随机生成的会话 ID，不采集姓名、账号、设备标识，服务端也不存 IP。

- 地址：`https://passive-sailfish-d0e1nvt8175333a.service.tcloudbase.com/log`
- 环境：`passive-sailfish-d0e1nvt8175333a`（PostgreSQL 版，体验版）
- 运行时：Nodejs20.19，HTTP 云函数，入口 `server.js`（`scf_bootstrap` 启动）

## 数据库

表结构：

```sql
CREATE TABLE IF NOT EXISTS behavior_events (
  id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  session_id TEXT NOT NULL,
  client_start BIGINT NOT NULL DEFAULT 0,
  server_time TIMESTAMPTZ NOT NULL DEFAULT now(),
  ua TEXT NOT NULL DEFAULT '',
  events JSONB NOT NULL,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX IF NOT EXISTS behavior_events_session_idx ON behavior_events (session_id);
CREATE INDEX IF NOT EXISTS behavior_events_time_idx ON behavior_events (server_time);
```

云函数的平台凭证在 `app.rdb()` 中映射为 `anon` 角色，因此需要写入权限。
只授予 INSERT 和序列权限，不授予 SELECT，匿名端无法读取数据：

```sql
GRANT INSERT ON public.behavior_events TO anon;
GRANT USAGE, SELECT ON SEQUENCE public.behavior_events_id_seq TO anon;
```

## 部署

```bash
cd server/behavior-log
npm install
tcb fn deploy behavior-log --httpFn --force --dir . -e passive-sailfish-d0e1nvt8175333a
```

注意：CloudBase 网关会按请求 Origin 自动补 `Access-Control-Allow-Origin`，
函数自己再写这个头会和网关的值拼成 `origin,*`，浏览器会判定 CORS 失败。
因此 `index.js` 只返回 `Content-Type`。

## 导出数据

导出的前提是本机能用 `tcb` 登录**对这个环境有权限的账号**（就是部署环境的账号），
不需要数据库密码。游戏端和云函数使用的匿名角色只有 INSERT 权限，读不了数据；
没有账号的成员需要先加入环境，或请有权限的成员按下面方法导出后转交。

### 一条命令导出 CSV（推荐）

```bash
cd server/behavior-log
npm install -g @cloudbase/cli   # 已安装可跳过
tcb login                       # 浏览器里用有权限的账号授权，一次即可
node export.js --out D:/展览数据
```

脚本会分页查询并把两份文件写到输出目录：

- `sessions.csv`：每个会话一行，列是 `session_id`、`started_at`、`last_seen`、
  `batches` 上报批次数、`events` 事件条数、`user_agent`（浏览器标识）。
- `events.csv`：每个事件一行，列是 `session_id`、`server_time`、`t_ms`
  （页面打开后的毫秒数）、`event` 事件名、`props` 事件属性（JSON）。

参数：

- `--out <目录>`：输出目录，默认当前目录下的 `export/`。
- `--from 2026-10-29` / `--to 2026-10-30`：按服务器时间筛选，`to` 不含当天之后的数据；可只写一个。
- `--env <环境 ID>`：默认读同目录 `cloudbaserc.json` 里的 `envId`。

CSV 带 UTF-8 BOM 和 CRLF 换行，Excel 直接双击就能打开中文。

### 直接执行 SQL

临时看数或写自己的统计时，用 `tcb db execute`，结果会直接打印：

```bash
tcb db execute -e passive-sailfish-d0e1nvt8175333a --sql "SELECT count(*) FROM behavior_events;"

# 每天的体验人数和完成单数
tcb db execute -e passive-sailfish-d0e1nvt8175333a --sql "SELECT date(server_time) AS day, count(DISTINCT session_id) AS sessions, count(*) FILTER (WHERE events @> '[{\"n\":\"finish\"}]') AS finishes FROM behavior_events GROUP BY 1 ORDER BY 1;"
```

加 `--json` 得到机器可读的结果（`Columns` 和 `Rows`，每行是一个 JSON 数组字符串），
`tcb db execute --help` 里还有 `--role postgres` 等选项。

### 控制台导出（不装命令行）

CloudBase 控制台 → 数据库 → PostgreSQL → SQL 编辑器，执行上面的 SQL，
用结果面板的导出按钮下载 CSV。适合只取一份汇总表、或者临时排查问题。

### 注意事项

- 导出的数据包含体验者的游戏轨迹和浏览器标识，只用于展览效果分析，
  对外分享前先去掉 `user_agent` 列和 `pos` 事件。
- 用 `--role postgres` 才能修改表结构或删除数据；日常导出保持默认角色即可，
  避免误改线上数据。

## 数据

事件名：

| 事件 | 含义 | 属性 |
| --- | --- | --- |
| `session` | 页面加载 | `w`/`h` 视口、`touch` 是否触屏 |
| `offer` | 生成待接订单 | `seed`、`pick` 取餐路程、`drop` 送达路程 |
| `start` | 接单开始 | `seed` |
| `pickup` | 取到餐 | `sec` 已用秒数 |
| `pos` | 位置轨迹（每 2 秒） | `x`/`z` 坐标、`yaw` 朝向、`d` 距目标、`left` 剩余秒 |
| `finish` | 订单结算 | `ok`、`why`（`timeout`/`hit`）、`sec` |

常用查询：

```sql
-- 每天体验人数与订单完成率
SELECT date(server_time) AS day,
       count(DISTINCT session_id) AS sessions,
       count(*) FILTER (WHERE events @> '[{"n":"finish"}]') AS finishes
FROM behavior_events GROUP BY 1 ORDER BY 1;

-- 每条轨迹
SELECT session_id, e->>'t' AS t_ms,
       (e->'p'->>'x')::real AS x, (e->'p'->>'z')::real AS z,
       (e->'p'->>'yaw')::int AS yaw
FROM behavior_events, jsonb_array_elements(events) e
WHERE e->>'n' = 'pos' ORDER BY session_id, t_ms;
```
