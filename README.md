# 大城市送外卖：程序化 3D 路网

用 Godot 4.7 打开项目，按 **F6** 运行 `scenes/city_road_demo.tscn`，或按 **F5** 运行整个项目。红色、黄色、青色分别表示主干路、次干路、支路。场景脚本的 Inspector 中可调整地图宽高、随机种子、道路密度、三类道路红线宽度。1 世界单位 = 1 米。

生成器先构造道路节点与路段，再用同一份数据绘制道路和交叉口。主干路间距随道路密度在 600～800 米之间变化；次干路位于主干路之间；部分街区生成连接两条次干路的支路。随机种子决定哪些街区生成支路，相同参数与种子会生成同一张路网。红线以深灰色底面表示，彩色部分是独立设置的车行道示意，宽度为红线的 55%。车行道及地面有物理碰撞体。`RoadNetwork.find_route(network, 起点节点编号, 终点节点编号)` 返回一条连通路径上的节点编号。

运行时控制台会输出硬规则校验结果、节点与路段数量及建议范围的偏离。生成器不创建地块或地块出入口，因此出入口规则报告为“未适用”。为让支路接入次干路，部分次干路交叉口间距会小于建议的 300 米，但仍满足 150 米硬下限。当前路网为平面直角路网，不含高架、匝道和交通信号。

可用以下命令运行自动校验：

```powershell
godot --headless --path . --script res://tests/test_road_network.gd
```

## Git 与资源文件

`.gitattributes` 将模型、贴图、音频、字体及 Godot 二进制资源交给 Git LFS；`.gd`、`.tscn`、`.tres`、`.svg` 等可编辑文本仍由普通 Git 管理。新克隆本仓库的电脑需要先安装 Git LFS，并在仓库中执行 `git lfs install --local`。当前提交历史没有需要迁移到 LFS 的二进制资源。

`.tscn` 和 `.tres` 使用 `gdmerge` 处理本地三方合并。每位协作者需在自己的电脑安装它，并在仓库中运行一次 `gdmerge git-install`；仓库中的 `.gitattributes` 会共享文件匹配规则，本机的 Git 合并驱动配置不会自动随仓库同步。安装命令：`cargo install gdmerge --version 0.3.6 --locked`。
