# 动态车流

主场景的 `TrafficSystem` 继续使用原 `RoadNetwork`、`TrafficRoute` 和 `TrafficCar`；不创建第二套道路。World 生成后，TrafficSpawner 先以 CityContent 的玩家起点建立局部车流，玩家完成初始落位后接入 Player；之后每 0.5 秒按玩家位置更新。Seed、道路、订单、导航和建筑 Chunk Streaming 互不重新生成。

## 修复的问题

旧系统在初始化时随机挑选全图路段，2400 米地图有 214 辆占位方块车，但玩家附近可能很稀疏。更直接的移动问题是 `AnimatableBody3D.sync_to_physics = true`：原脚本按帧写入 position，物理同步会覆盖该位置，导致离树调用 `advance()` 的旧测试通过、实际场景中的车辆却停在原处。现关闭该同步，交通管理器在物理帧推进车辆；四个 Seed 的场景内位移测试均通过。

## 模型与碰撞

`traffic_model_catalog.gd` 记录 `assets/models/汽车模型` 中全部 11 个 GLB 的完整层级包围盒；`build_traffic_catalog.gd` 可在源模型改变后重新生成。TrafficCar 从这 11 个模型中按 Seed、路段和生成序号选择外观，按包围盒等比缩放到单车道约 1.9×4.2 米上限，最低点贴到路面附近。物理碰撞和玩家命中 Area 使用与模型相应的简化 BoxShape3D。旧 `Body` 节点保留为隐藏的回退网格，实际可见的是 `CarModel`。模型加载由 Godot 的资源缓存复用；对象池优先取同模型车辆，回收时退出场景树，关闭其物理更新。交通节点退出场景时会释放池中脱离树的车辆。

车辆仍沿原右侧单向车道行驶，通过 RoadNetwork 邻接关系在路口优先直行、必要时转弯或掉头。路口连接以原折线路径衔接。速度逐步升降，转弯前减速；前方同向车辆过近时减速/停车，非信控路口给更接近冲突点的车辆让行。靠近玩家行驶方向前方时尝试减速。车辆保留原 PLAYER 层碰撞和撞车失败信号。

## 参数

`scenes/traffic/traffic_system.tscn` 的 TrafficSystem Inspector 可调：

| 参数 | 默认 | 用途 |
|---|---:|---|
| enable_traffic | true | 开关交通 |
| traffic_density | 1.0 | 按附近主/次/支路长度加权的目标密度倍率 |
| max_vehicles | 30 | 活动车辆及备用池各自的硬上限 |
| traffic_spawn_radius | 220 m | 在附近路段补充车辆 |
| traffic_despawn_radius | 320 m | 超出后回收；可见车辆延后到更远距离 |
| traffic_update_interval | 0.5 s | 重新计算活动道路和补车，非每帧扫描全图 |
| min_vehicle_spacing | 24 m | 出生与跟车的最低参考距离 |
| min_speed_kmh / max_speed_kmh | 25 / 45 | 道路等级目标车速的允许范围 |
| acceleration_mps2 / braking_mps2 | 2.2 / 5.0 | 平滑加速与制动 |
| show_traffic_debug | false | 每两秒向 Godot 输出活动道路、车辆、生成、回收及池数量 |

主干路基础目标 12 m/s、次干路 9 m/s、支路 7 m/s（约 43/32/25 km/h），含 ±10% 变化，最后由速度上下限裁剪。主、次、支路的密度权重为 1.0、0.6、0.2；支路进一步稀疏化。每个路段为双向各一条汽车车道，原路网不提供更多车道数，车流不推断虚构车道。目标数量受 `max_vehicles` 限制，常规更新最多补两辆；近 48 米内、镜头内和已占用车道附近避免新车。摄像机内远车会延迟回收，绝对最大活动范围为卸载半径再外加 100 米。Debug 时仍可用原 F3 俯视视角观察。

## 验证与边界

`test_traffic.gd` 保留原车道数学、长距离路径、撞车语义；新增 `test_traffic_streaming.gd` 在 Seed 118、1、42、2026 上验证真实物理帧位移、附近车辆上限、换区回收和对象池，并实例化全部 11 个模型。主场景冒烟测试改为检查附近有车且不超过上限，同时继续验收启动、订单与导航。全部十二组 Godot headless CI 测试通过。

无界面测试中，Seed 118 主场景启动后观察到 11 辆附近车辆；四 Seed 独立交通测试首次建立车流时各有 7 辆，随着更新补充。初始车辆在约 200 个物理帧内实际前进至少 10 米；移到远处后旧区域车辆回收，活跃数不超过 18（该测试配置）。这不代表 GPU 帧率。

需要在可见 Godot 窗口检查模型车头朝向、车轮/贴地细节、路口转弯观感、镜头前刷新、真实交通密度和帧率。现有路口让行与前车检测是简单规则，尚无正式信号灯、变道、超车或复杂避障；过密配置仍可能产生拥堵。玩家骑行控制代码未调整。
