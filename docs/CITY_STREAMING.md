# Seed 城市与区块加载

主场景现在使用任意 Seed 的布局和动态模型加载。`scenes/city/city_population.tscn`、`delivery_sites.json` 以及旧烘焙工具仍保留为 Seed 118 历史样例，主场景不再实例化这个固定布局。原道路生成、地块划分、任务数据、导航、玩家和交通实现未更换。

## 编辑器使用

1. 打开 `scenes/main/main.tscn`，选中 World，修改 `seed`，点击 Inspector 的“重新生成城市”。Seed 是唯一城市种子，不另设第二份 global_seed。默认仍为 118。修改数值本身不重建地图，初次打开场景会自动生成一次预览。
2. 选中 `World/CityStreaming` 配置模型预览。必要时右键 World 启用“可编辑子节点”；也可直接打开 `scenes/world/world.tscn` 修改默认配置。
3. `editor_preview` 的“全城简化”显示所有建筑的实际尺寸方块；“局部精细”在 `preview_position` 周围加载精细模型；“全城精细（昂贵）”分帧加载全城模型。选择模式/位置后点击“刷新预览”。建议用局部精细查看任务位置，避免一次显示数千个模型。
4. F5 启动游戏。精细模型随 Player 的实际位置加载，远景方块与碰撞保持常驻。进入游戏无须先运行烘焙脚本。

编辑器的选择只影响预览，游戏使用玩家位置。Seed 和区块大小应在启动前设置；改变正在运行的整座地图应重新启动游戏，使现有订单管理器按新地图初始化。本次未新增游戏中途切换城市/迁移活动订单的玩法。

## 参数（World/CityStreaming）

| 参数 | 默认 | 说明 |
|---|---:|---|
| chunk_size | 100 米 | X/Z 规则分块，负坐标使用 floor；改变后刷新/重新生成 |
| load_radius | 2 | Chebyshev 方形范围，最多 5×5 个附近区块 |
| unload_radius | 3 | 卸载外圈；内部至少保持 load_radius+1，避免边界抖动 |
| stream_update_interval | 0.2 秒 | 玩家位置检查间隔，不每帧重建布局 |
| instances_per_frame | 2 | 每帧最多实例化的模型数，包含树木/路灯 |
| frame_budget_ms | 3 毫秒 | 批次软预算；单次模型实例化不能中途打断 |
| enable_streaming | true | false 时分帧加载全城精细模型，用于对比；刷新后生效 |
| preview_position | (0,0,0) | 编辑器局部预览中心，World 本地坐标 |

现有玩家默认速度为 5 m/s，默认两圈覆盖至少约 200 米前方区域。未模拟新增高速骑行系统。瞬移或提高移动速度时，精细模型可能尚在队列中；远景方块、碰撞、任务标记和入口铺装立即可用，订单不会等待模型加载。提高半径可增加提前加载距离，但会增加实例数量。

## 数据与资源分层

- `CityPopulationLayout`：复用 `CityContent.buildings/lots/sites`，为每一个地块确定模型、等比缩放、朝向、位置、入口和装饰。随机数独立绑定城市 Seed 与 building ID，资源访问和区块加载顺序不参与随机过程。所有模型和装饰按中心位置归属区块。
- `city_model_catalog.gd`：18 个已筛选资源的完整层级包围盒元数据。布局阶段不加载 GLB。原目录共检查到 7 个取餐、7 个送餐、60 个其他建筑和 39 个装饰 GLB；桥梁、未知用途物件等未盲目加入建筑池。当前池沿用已布置的 6 个餐饮模型、7 个送餐模型、3 个其他建筑，另用 Asset_0004 树木与 Asset_0027 灯杆模型。
- `CityBuilder`：常驻全城低细节建筑、与精细模型包围盒一致的简单碰撞、任务标记和入口铺装。精细建筑就绪才隐藏该建筑的方块；卸载时恢复。导航仍只烘焙原道路碰撞分组，任务点仍来自原 CitySite。
- `CityStreaming`：维护实际加载区块、距离排序队列和有限模型缓存。游戏中通过 Godot 资源加载 API 异步读取，所有实例化和场景树操作在主线程完成；编辑器使用主线程分帧资源读取，避开编辑器导入与异步加载的竞争。缓存最多为目录中这 18 种模型，不随探索位置无限增长。
- `WorldGenerator`：生成原道路和城市数据，然后生成完整人口布局、构建简化表现、配置流式加载。区块更新不会调用道路/城市生成器。

装饰放在各建筑侧边退让带，入口中轴留空；每三个地块在一侧使用灯杆，其余为树木。它们不附加实体碰撞，避免引入新的路障。本次没有新增动态灯光、交通信号 AI 或建筑室内。

## 验证与测量

运行 `godot --headless --path . --import` 后，运行已有九组测试，以及：

```sh
godot --headless --path . --script res://tests/test_city_population.gd
godot --headless --path . --script res://tests/test_city_streaming.gd
```

CI 已加入这两组测试。静态测试保留已保存的 240 栋 Seed 118 布局空间检查，运行时切换/加载回归移入 streaming 测试。

四个 Seed 的空间、确定性、订单生成/取餐/送达、离开返回、逆序加载、12 次探索跳转、分帧实例上限及卸载清理测试通过。空间测试覆盖全部建筑和装饰的道路红线、交叉口、相互重叠、任务点一米净空及入口路径。简化碰撞保持常驻，因此卸载不会改变可通行空间。

一次云端 Godot 4.7.2 headless 测量如下（包含道路、城市与布局生成；不是 GPU 渲染性能）：

| Seed | 完整建筑 | 装饰 | 非空区块 | 生成耗时 ms | 商家附近精细实例（含装饰） | 测试观察到的批次峰值 ms |
|---|---:|---:|---:|---:|---:|---:|
| 118 | 1637 | 3274 | 250 | 90 | 261 | 1.808 |
| 1 | 1679 | 3358 | 258 | 106 | 273 | 1.289 |
| 42 | 1699 | 3398 | 258 | 112 | 164 | 1.014 |
| 2026 | 1645 | 3290 | 254 | 98 | 192 | 1.278 |

上述测试移到城外后精细实例均降到 0，回到原地点后数量与变换恢复一致；资源缓存保持有限。首次冷加载和具体机器会影响结果，3 ms 是软预算，不能据此承诺所有帧都小于 3 ms。未测量 GPU 帧率或显存。

编辑器工具上下文已验证局部预览生成 222 个模型、Seed 不自动重建及按钮刷新；标准 headless 编辑器打开局部预览场景正常退出，没有资源错误。没有进行可见窗口的 GPU 视觉验收。

## 仍需人工检查

在真实 Godot 3D 视口检查模型门面朝向、贴图、灯杆外观/比例、低细节切换突变、实际帧率和快速驾驶体验。自动包围盒检查不等于逐个模型的门洞识别；所有任务点仍在门前可达地面，建筑内部不开放。当前以固定模型目录版本保证确定性，修改源模型或目录时应重新测量包围盒并运行空间测试：

```sh
godot --headless --path . --script res://scripts/dev/build_city_catalog.gd
```

历史静态布置工具仍可手动重建 Seed 118 样例，但不会参与实时流式系统。

2026-10-29 回归补充：`instance_count()` 统计当前 `loaded_chunks` 内精细建筑和装饰节点，不包含常驻方块或碰撞。滞回会保留前一位置的外圈区块，因此只有从相同空载状态进入同一地点，才能比较重访前后的实例数。测试现已按此条件比较，仍要求完全相等，并检查释放的旧节点与区块内 ID 唯一性。
