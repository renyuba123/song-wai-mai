# 展览行为数据导出

展览页采集的玩家行为保存在腾讯云 CloudBase 的 PostgreSQL 数据库里。
本文写给需要取数、但手上没有服务器终端的成员：按下面的步骤可以在自己的
电脑上把数据导成 CSV，不需要改动云端代码，也不需要等原维护者在场。

- 环境：`passive-sailfish-d0e1nvt8175333a`（体验版，地域 ap-shanghai，
  2027-04-29 到期）
- 数据表：`public.behavior_events`
- 写入入口：`https://passive-sailfish-d0e1nvt8175333a.service.tcloudbase.com/log`
- 采集内容：页面加载、待接订单、接单、取餐、每两秒一次的位置、订单结算；
  客户端只带随机会话 ID，不采集姓名、账号或设备标识，服务端也不存 IP。

## 先解决权限

云端只给云函数的平台身份 `anon` 授予了 INSERT（写入）权限，没有 SELECT。
所以匿名接口和游戏页面都读不到数据，导出必须使用有读权限的账号：

- **腾讯云账号或子账号**：能登录 CloudBase 控制台、能看到这个环境即可。
  推荐由主账号在腾讯云访问管理里新建子账号，关联 CloudBase 的预设策略
  `QcloudAccessForTCBRole`，再用自定义策略把权限限定到这个环境。
- **CloudBase CLI 的 API Key**：如果不想加子账号，主账号可以在
  [API Key 管理](https://console.cloud.tencent.com/cam/capi) 生成一对
  SecretId/SecretKey 私下交给成员。密钥只放在本机环境变量或登录缓存里，
  不要写进仓库、聊天记录或二维码。
- **数据库账号**：只用于登录控制台的 DMC 数据库管理，在
  「PostgreSQL 数据库 → 数据库设置 → 账号管理」里新建。它不能替代
  CloudBase 控制台权限。

原维护者离开前，至少要把一种方式交接好；否则成员只能看到控制台入口，
无法真正查库。

## 方法一：仓库脚本（推荐，已在 2026-10-29 实测）

脚本 `tools/export_behavior_data.py` 只执行 SELECT，通过 CloudBase CLI
取数，再在本地生成 CSV。需要 Python 3.8 以上和 Node.js 18 以上。

1. 安装并登录 CloudBase CLI：

   ```bash
   npm install -g @cloudbase/cli
   tcb login
   tcb env list
   ```

   `tcb login` 默认走设备码：终端给出一个网址和确认码，用有权限的腾讯云
   账号在浏览器里确认即可。也可以非交互登录：

   ```bash
   tcb login --apiKeyId <SecretId> --apiKey <SecretKey>
   ```

   `tcb env list` 能看到 `passive-sailfish-d0e1nvt8175333a` 就说明权限正常。
   如果提示地域不对，加 `--region ap-shanghai`。

2. 在仓库根目录导出全部记录：

   ```bash
   python tools/export_behavior_data.py
   ```

   默认写到 `exports/behavior-<日期时间>/`。也可以指定时间范围和输出目录：

   ```bash
   python tools/export_behavior_data.py \
     --out exports/behavior-20261029 \
     --since "2026-10-29 00:00:00+08" \
     --until "2026-10-30 00:00:00+08"
   ```

   `--since` 是下限（含），`--until` 是上限（不含），都按数据库的
   `server_time` 过滤；时间字符串直接写进 SQL，用单引号包起来即可。
   数据量大时可以调小 `--batch-size`（默认 500），脚本会按 `id` 分批读取。

3. 输出文件：

   | 文件 | 内容 |
   | --- | --- |
   | `behavior_events.csv` | 一条数据库记录一行，`events` 列保留原始 JSON |
   | `behavior_events_events.csv` | 一条事件一行，含事件名、毫秒时间和属性 JSON |
   | `summary.json` | 行数、会话数、各事件计数和导出参数 |

   CSV 带 UTF-8 BOM，Excel 直接双击打开不会乱码。

4. 脚本会打印进度和汇总。2026-10-29 17:02 的实测结果：108 条记录、
   14 个会话、298 个位置点；说明这条路径可用。

## 方法二：控制台 DMC（不装命令行也能用）

适合只需要临时看几行、或者电脑上没有 Node.js 的成员。

1. 打开 CloudBase 控制台，进入环境 `passive-sailfish-d0e1nvt8175333a`。
2. 进入「PostgreSQL 数据库 → 数据库设置 → 账号管理」，新建一个数据库账号；
   账号名、主机、密码按页面提示填写，密码自己保存好。
3. 点「数据库管理」进入 DMC 页面，用刚才的账号密码登录。
4. 选择「SQL 窗口」，执行下面的查询。
5. 需要整表或查询结果时，点 DMC 页面的「悬浮工具 → 导入导出」，
   按页面提示选择表和导出范围。不同版本的 DMC 按钮位置可能略有差异，
   以控制台当前界面为准。

如果 DMC 登录时报权限或认证失败，不要改内置管理角色的密码，
先确认账号是不是在这个环境里创建的；反复失败就换方法一。

## 方法三：psql / pg_dump（仅在拿到外网连接信息时）

CloudBase 的体验版共享集群通常不提供数据库外网地址，三条 TCP 直连路径
（公网、云托管内网、同 VPC）都不通。只有在控制台明确给出可用的外网地址、
端口、库名、账号和密码时才用这一节。

```bash
export PGHOST=<控制台给出的地址>
export PGPORT=5432
export PGDATABASE=postgres
export PGUSER=<账号>
export PGPASSWORD=<密码>

# 只导这张表的数据，CSV 带表头
psql "sslmode=require" -c "\copy (SELECT id, session_id, client_start, server_time, ua, events::text AS events, created_at FROM public.behavior_events ORDER BY id) TO 'behavior_events.csv' WITH (FORMAT csv, HEADER true, ENCODING 'UTF8')"

# 或者做逻辑备份
pg_dump "sslmode=require" --data-only --table=public.behavior_events \
  --column-inserts --file=behavior_events.sql
```

`pg_dump` 出来的备份不要当成平台备份；CloudBase 的自动备份和回档在
控制台「数据库 → 备份与回档」里，两者用途不同。

## 表结构

```sql
CREATE TABLE IF NOT EXISTS behavior_events (
  id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  session_id TEXT NOT NULL,
  client_start BIGINT NOT NULL DEFAULT 0,
  server_time TIMESTAMPTZ NOT NULL DEFAULT now(),
  ua TEXT NOT NULL DEFAULT '',
  events JSONB NOT NULL,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);
```

- `session_id`：页面打开时随机生成的会话标识，同一局游戏不变。
- `client_start`：客户端记录的会话开始毫秒时间戳。
- `server_time`：服务端落库时间，按这个字段筛日期。
- `ua`：浏览器 User-Agent，用来区分手机和桌面；里面有浏览器版本信息，
  导出后不要发到公开群或提交进仓库。
- `events`：一次批量上报的事件数组，每个元素是
  `{"n": 事件名, "t": 相对毫秒, "p": {属性}}`。

## 事件字典

| 事件 | 含义 | 属性 |
| --- | --- | --- |
| `session` | 页面加载 | `w`/`h` 视口、`touch` 是否触屏 |
| `offer` | 生成待接订单 | `seed`、`pick` 取餐路程、`drop` 送达路程 |
| `start` | 接单开始 | `seed` |
| `pickup` | 取到餐 | `sec` 已用秒数 |
| `pos` | 位置轨迹（每 2 秒） | `x`/`z` 坐标、`yaw` 朝向、`d` 距目标、`left` 剩余秒 |
| `finish` | 订单结算 | `ok`、`why`（`timeout`/`hit`）、`sec` |
| `probe` | 部署时手工自检写入 | 测试用，分析玩家数据时排除 |

`probe` 只出现在 2026-10-29 的联调记录里，不是玩家行为。下面的查询默认
用 `session_id NOT LIKE 'probe%'` 把它排除。

## 常用查询

在 DMC 的 SQL 窗口里执行，或者把 SQL 贴给 `tcb db execute`：

```bash
tcb db execute -e passive-sailfish-d0e1nvt8175333a \
  --sql "SELECT count(*) FROM public.behavior_events" --json
```

注意：`tcb db execute` 一次返回一个结果集；导出整表请用方法一的脚本，
不要直接把大结果集打在终端里。

每天体验人数、订单数和完成率：

```sql
SELECT date(server_time) AS day,
       count(DISTINCT session_id) AS sessions,
       count(*) FILTER (WHERE events @> '[{"n":"finish"}]') AS finishes,
       count(*) FILTER (WHERE events @> '[{"n":"finish","p":{"ok":true}}]') AS completed
FROM public.behavior_events
WHERE session_id NOT LIKE 'probe%'
GROUP BY 1 ORDER BY 1;
```

每次接单的耗时和结果：

```sql
SELECT session_id,
       min(server_time) AS started_at,
       max((e->'p'->>'sec')::int) FILTER (WHERE e->>'n' = 'finish') AS seconds,
       max(e->'p'->>'why') FILTER (WHERE e->>'n' = 'finish') AS result
FROM public.behavior_events, jsonb_array_elements(events) e
WHERE session_id NOT LIKE 'probe%'
GROUP BY 1 ORDER BY 2;
```

轨迹点（可以直接用来画热力图或回放）：

```sql
SELECT session_id, e->>'t' AS t_ms,
       (e->'p'->>'x')::real AS x, (e->'p'->>'z')::real AS z,
       (e->'p'->>'yaw')::int AS yaw, (e->'p'->>'d')::real AS distance
FROM public.behavior_events, jsonb_array_elements(events) e
WHERE e->>'n' = 'pos'
  AND session_id NOT LIKE 'probe%'
ORDER BY session_id, t_ms;
```

各事件出现的次数：

```sql
SELECT e->>'n' AS event_name, count(*) AS n
FROM public.behavior_events, jsonb_array_elements(events) e
WHERE session_id NOT LIKE 'probe%'
GROUP BY 1 ORDER BY 2 DESC;
```

## 隐私与文件管理

- 数据里没有姓名、账号、手机号或设备唯一标识，但 `ua` 和轨迹仍然能描述
  某一次参观；导出文件按内部资料处理。
- `exports/` 已加进 `.gitignore`，不要把导出的 CSV、JSON 或数据库备份提交
  进仓库，也不要贴到公开的二维码页面。需要共享时走网盘或私聊。
- 云函数的 `anon` 账号只有 INSERT 权限，不要为了“让页面直接读数据”
  给它开 SELECT；二维码 3 号的页面如果要展示统计，应当另做只读接口，
  只返回聚合结果。
- 需要删掉联调数据时，先在 DMC 里确认 `session_id LIKE 'probe%'` 的行数，
  再按会话删除；不要整表清空。

## 常见问题

- **`tcb` 找不到**：确认 `npm install -g @cloudbase/cli` 成功，重开终端；
  Windows 上 `tcb` 是 `tcb.cmd`，一般已在 PATH 里。
- **`tcb env list` 是空表**：账号没有这个环境的权限，或者地域不对。
  加 `--region ap-shanghai` 再试；仍然为空就找主账号补授权。
- **登录过期 / 设备码失效**：重新执行 `tcb login`。设备码一次有效，
  过期后重新生成即可。
- **SQL 报权限错误（42501）**：当前角色读不了这张表。`tcb db execute`
  默认用登录账号的身份执行，不要加 `--role anon`；DMC 则确认用的是
  账号管理里新建的数据库账号。
- **导出很慢或终端刷屏**：调小 `--batch-size`，或者先用 `--since`
  按天导出。数据量再大时按天拆成多个目录，不要一次读完整张表。
- **环境到期**：体验版到 2027-04-29，续期或迁移要提前处理；到期后
  云函数、静态托管和数据库都会停。
